# infinite-context-rules：早期规则原型（历史对照）

名称表达的目标是让用户与执行任务的 Agent 感受不到压缩造成的任务中断、遗忘或重复探索；这是待验证的设计目标。

2026-10-10，实验实现；尚无真实任务收益证据。由 Cliff 的机械摘要规则构建，
不是原论文复现，也不替换原 CliffCompaction。主模型及其推理设置保持不变。

## 已实现

- `spec` 工具输出及对应调用原文保留；用户、系统、开发者消息及媒体保留。
  spec 识别沿用框架路径/命令分类，不等于完整的语义约束识别。
- 可选近期工作集合：最近 `work_turns` 个框架轮次涉及的路径，保留其最新观察
  和调用配对。保护只在本次决策有效，不把所有旧文件版本永久固定。
- 请求估计超过 `t` 才评估，机械压缩保留最近 1、K、2K 轮的候选。
  优先选达到 `target` 且保留轮次最多的候选；都达不到时选最短候选。
  这些长度是估算的实际输入 token（ctxpress.core.sizes）。
- 评估间隔至少 `cooldown` 次请求；达到 `emergency` 或收到明确超长错误时
  可提前清理，但仍不删保护内容。目标与 emergency 都不是硬容量保证；
  保护内容过多时仍可能超限，宿主原生压缩或错误处理保持原有行为。
- 每次只从当前可见原始片段产生机械摘要，不将模型生成的新措辞提交到历史。
  旧机械摘要在后续批次中丢弃；其未受保护的历史不保证长期召回。

## 独立预测模型

`predictor_mode` 为 `off`（默认）、`shadow` 或 `control`。
启用后必须显式提供 `predictor_model`，不会偷偷使用主模型。
通过框架 `model_text` 调用同一上游上的指定模型，用途为
`compaction_prediction`；实际辅助输入、输出和费用由现有模型服务记账。
另一个供应商的端点需要已有宿主服务适配或独立 Python 服务，单独改模型名
不等于跨供应商接入。用户所说的“jev”尚待确认，未预填或调用猜测的模型。

模型读有限的近期证据与候选大小、被处理内容类型数量，输出统一预测视野
（1–64 次请求）、各候选的额外恢复/探索请求数及归一化任务分数损失。
JSON、候选 ID、覆盖完整性、重复项、数值范围及有限性均由程序验证。
错误、超时、无服务或不合法预测在 control 中保留历史；下一次评估遵守冷却。
shadow 始终执行规则选择，预测仅供事后校准。

control 对质量损失估计不超过 `max_quality_loss` 的候选计算：

```
gain = cached_price * saved * horizon
       - (uncached_price - cached_price) * retained_suffix
       - extra_requests * (cached_price * after
                            + uncached_price * saved
                            + output_price * estimated_extra_output)
```

只选择正收益最大的候选，否则不动。这里使用引擎的配置价格单位，是保守近似，
不是美元账单或校准后的性能保证。恢复量暂用被删除体积近似，可能高估；
预测器此次调用在选择时已是沉没成本，实际账单仍计入它，不能据 `gain`
判断整个预测器是否划算。与 off、shadow 的端到端总费用对照负责检验这点。
部署实验前须将引擎价格假设与试验配置对齐，不能依赖旧模拟默认比例。

`last_decision` 提供最近一次决策，Responses 改写遥测的 `method_decision`
记录候选、预测和最终选择；未发生决策的请求不重复记旧值。记录不包含证据原文。
预测没有训练或校准过，0.02 只是默认筛选阈值，不代表失败概率或质量保证。

## 使用与对照

```bash
ctxpress codex --method infinite-context-rules --args '{"t":100000,"target":50000,"work_turns":3}' -- exec "任务"
```

明确模型身份后，可在 args 中加入 `predictor_mode: "shadow"` 与实际的
`predictor_model`。确认模型支持当前上游、调用用量完整且预测可校准后，才比较
control 的真实效果。需要该模型生成自由文本摘要属于后续独立消融，本版不启用。

`configs/infinite-context-methods.json` 是可放入已有评测计划 `methods` 字段的四组配置，
不是直接可运行的完整评测计划。前两组隔离规格保护的收益；后两组隔离工作集合
保护的增量。后两组改变了批处理方式，不能把它们与原 Cliff 的所有差异都归因于保护。
所有组应固定宿主、主模型、任务、推理预算和费用口径；同仓库不同检查点不能充当
多个独立仓库。正式指标为任务评分、里程碑通过、回归失败、完整总费用及用时。
恢复、搜索和重复压缩只作为机制指标，不能替代终局结果。

本轮仅做本地合成测试，不启动已有调度队列、不更改正在运行的评测配置。
