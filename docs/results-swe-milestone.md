# SWE-Milestone 结果

最后更新：2026-10-20。18 个论文方法配置与 Vanilla Codex 在同一设置下真实运行、官方评分。轻场景全部完成；重场景因模型额度用完停止，完成 4 个方法。

## 设置

| 项 | 值 |
|---|---|
| 宿主 | Codex 0.161.0（Code Mode），`HostDefault` 为对照 |
| 模型 | gpt-6.1-sol，reasoning medium，Fast 档（`run.service_tier="fast"`） |
| 窗口 | 128k（v4 窗口参数：触发点 T = 0.8W = 102400，余量 H = W − T） |

| 重复 | 每个方法每个场景 1 次 |

- 多数方法与 Vanilla（81.7）相差不到 1 分。只有 1 次运行，1 分以内的差距不可区分（Vanilla 在 navidrome 上 3 次为 86.8 / 69.4 / 91.0）。
- “依赖训练”指论文效果来自作者训练的策略或摘要模型，这里只接入机制、由同一通用模型驱动，结果不代表论文方法本身。可信的结论只有 4 条：AgentDiet 与 ComplexityTrap 掉分，ComplexityTrap 与 CWL 成本更高。
- AgentDiet 低分：SWE-Milestone 的需求文档由 Agent 用 `cat` 读入，属于工具输出；AgentDiet 按作者规则把较早的长工具输出压到 20–50%，需求文档也被压缩，Agent 反复重读、仍漏改测试桩。这是作者方法的原样行为，不是实现错误。
- 成本高的原因：CWL 缓存命中正常，但输入总量约 1.3 亿 token，是 Vanilla（7300 万）的 1.8 倍；ComplexityTrap 和 FoldAct 输入量与 Vanilla 相近，但改写旧历史使后续前缀失去缓存，命中只有 56–58%。
- 成本口径：按记录用量和评测配置中声明的标准价格估算的 API 等价费用，包含写摘要、Codex 原生压缩等辅助调用。实际运行用 ChatGPT 登录和 Fast 档，真实计费口径不同（Fast 档单价更高）。

## 有效性

- 每个结果都经执行健康检查：无请求失败、无回合失败、方法工具调用都有对应的输出记录。不满足的判无效并补跑，不计入本表。
- 登录刷新失败（容器内无法刷新登录）的回合判为无效（`auth_failure`）；任务启动前检查登录新鲜度。
- 方法工具调用刚发出就被 Codex 原生压缩收进摘要的情况不算路由失败（此前误判，已修复并复核）。

本项目自己的方法（infinite-context）尚未进入这轮真实评测，见 [infinite-context.md](infinite-context.md#本项目方法)。
